# Bookmarks

Bookmark sync defaults to Playwright driving installed Google Chrome. It reads the
X session from Chrome using the existing `sweet-cookie` dependency, opens a
separate temporary Chrome window, and captures bookmark responses generated by
normal page navigation and scrolling. No X API key, `xurl`, or `bird` is needed.
Chrome must have an active X session matching the selected Birdclaw account.
The temporary browser closes when sync finishes; credentials are held in memory. Page saves retry transient SQLite lock errors
up to three times. Run full sync before bulk tagging to reduce writer contention.

X currently redirects `/i/bookmarks` to `/i/history` with Bookmarks selected.
The importer supports the current timeline and user metadata shapes, full note
text, article previews, media variants, and quoted posts. Quotes are stored as
context, without creating bookmark memberships for them. Sync adds/updates local
records; it does not infer remote removals from an incomplete scan.

## Sync

Use Node 25.8.1 or 26, as required by this project. On this Mac, Node 26 is installed:

```bash
export PATH="/opt/homebrew/opt/node@26/bin:$PATH"
pnpm install --frozen-lockfile
pnpm dev
```

Use **Sync bookmarks** in the Bookmarks page, or:

```bash
pnpm cli sync bookmarks --account acct_alice --refresh --json
pnpm cli sync bookmarks --account acct_alice --max-pages 10 --refresh --json
pnpm cli sync bookmarks --account acct_alice --all --refresh --json
```

A single-page sync returns at most `--limit` posts. With `--max-pages` or `--all`,
X controls the page size. Scrolling is paced. A capped scan, repeated cursor, rate
limit, repeated posts, malformed later response, or stalled next-page load is reported as partial; already received pages
are retained. Existing local bookmarks are preserved. `--all` has a safety cap of
250 pages unless you set `--max-pages` explicitly.

If the wrong Chrome profile is selected, set `BIRDCLAW_CHROME_PROFILE` to a profile
name such as `Profile 2`, or a profile directory path. The importer checks the
visible signed-in handle before storing any posts. For unattended operation,
Chrome's cookie reader must already have any needed macOS Keychain access.

Explicit `--mode bird`, `--mode xurl`, and `--mode auto` remain available. `auto`
still tries xurl first and can use paid X API reads. The default bookmark path
uses Playwright and does not fall back to an API when Chrome fails. General
account jobs also use the configured bookmark transport when their shared mode
is `auto`; their other collection transports retain their existing behavior.

## JEV topic tags and relevance ranking

Set `TYPESAFE_API_KEY` in the environment, in `.env` inside Nalanda's data
directory, or in this package's ignored `.env` file, in that precedence order.
The caller's working-directory `.env` is not read. Only server code reads it. JEV is metered; it does not use the
OpenRouter key. The integration pins `jev-1.13.0` for reproducible judgments.

In the Bookmarks page, **Analyze with JEV** tags the first 50 loaded bookmarks.
Enter an optional question to rank that same set by relevance. Use the topic
selector to filter analyzed posts. Keyword search and Load more remain local.
Changing the question does not automatically start inference.

Each topic is an independent yes/no judgment, so a post can have multiple tags.
The UI shows tags whose probability is at least 0.8. This is an initial display
threshold, not a guarantee of correctness; raw probabilities stay in the cache.
Query relevance uses a shared 0–4 rubric and displays confidence separately.
Unknown topics remain untagged. JEV sees saved text, locally available quote text,
and article previews when imported; it does not read linked pages or see images.

The cache key includes post and quote content, author, topics, question, model,
and rubric version. Topic results are reused across different ranking questions.
Opening a view only reads cached judgments. Results are derived data in SQLite's
`sync_cache`; Git backups exclude that table, so restored archives can be
reanalyzed. No automatic full-library inference runs during sync.

```bash
pnpm cli bookmarks-analyze --account acct_alice --limit 20 --json
pnpm cli bookmarks-analyze "Tools for building AI agents" --account acct_alice --search "agent" --limit 30 --json
pnpm cli bookmarks-analyze --account acct_alice --all --json
pnpm cli bookmarks-analyze --account acct_alice --all --cached-only --json
```

`--all` tags the library in batches of 50 with four concurrent JEV requests. It
reports input-token usage and stops after a batch takes a run over 2M input tokens.
Rerunning resumes from cached judgments. It cannot be combined with a ranking
question or keyword filter. A failed service request stops the run; successful
judgments already cached are preserved.

Customize topics and the default sync transport in `~/.birdclaw/config.json`:

```json
{
  "bookmarks": {
    "mode": "playwright",
    "chromeProfile": "Default",
    "topics": ["AI and agents", "Software engineering", "Design", "Business"]
  }
}
```

Use 1–20 topic descriptions, each at most 100 characters. Topic changes invalidate
old judgment keys. The initial eight categories were chosen after reviewing a
93-post sample of this account's existing bookmarks; they cover AI, developer
tools, creative tools, business, marketing, science, learning, and personal life.

The other AI features (digests, discussion, profile analysis, inbox scoring) still
use their existing OpenAI integrations. JEV supplies structured judgments, not
prose summaries or chat. Bookmark tagging/ranking requires no OpenAI or OpenRouter
credits.
